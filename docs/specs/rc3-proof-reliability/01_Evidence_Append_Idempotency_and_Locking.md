# Evidence Append Idempotency and Locking

## Problem

The `0.2.0-rc.2` Bookmark API dogfooding run recorded that parallel HADARA evidence writes produced duplicate failed records. The current writer also allows a JSON report path to append evidence and then read the last JSONL line, which can report another process's record under concurrency.

## Goals

- Return the exact evidence record generated by the append path.
- Remove post-append "read last record" reporting.
- Expose explicit `--idempotency-key` on evidence write commands.
- Deduplicate only when an idempotency key is supplied.
- Recheck for duplicate keys immediately before append.
- Guard task evidence append with a task-scoped local lock.
- Keep keyless manual evidence append behavior unchanged.

## Command Surface

```bash
hadara evidence add-command \
  --task T-XXXX \
  --summary "pytest failed" \
  --result failed \
  --idempotency-key "command:T-XXXX:pytest-phase-6" \
  --json
```

`--idempotency-key` is optional. Absence means append a new evidence record, as today.

## Append Contract

`appendEvidenceWithResult` returns:

```typescript
{
  markdownPath: string;
  evidence: PersistedEvidenceRecord;
  markdownAppended: boolean;
  jsonlAppended: boolean;
  existing: boolean;
}
```

When a matching idempotency key already exists, no new Markdown or JSONL row is appended and the existing record is returned.

## Lock Boundary

The writer uses an ignored local task lock:

```text
.hadara/local/locks/evidence/<task-id>.lock/
```

The lock is acquired with `mkdirSync`, retried for a bounded period, and released with `rmdirSync`. On timeout the command returns/fails with:

```text
EVIDENCE_APPEND_LOCK_TIMEOUT
```

The lock protects only local filesystem writers. It is not a distributed lock.

## Acceptance

- `evidence add-command --json` reports the record returned by the append function, not the last JSONL line.
- Same idempotency key rerun returns the existing record and appends no duplicate rows.
- Concurrent same-key append leaves one JSONL record and one Markdown row.
- Keyless manual evidence continues to append multiple records.
- `EVIDENCE.md` and `evidence.jsonl` remain consistent for guarded append operations.
