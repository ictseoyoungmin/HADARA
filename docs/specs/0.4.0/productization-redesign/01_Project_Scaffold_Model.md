# 01 Project Scaffold Model

## Goal

Define the HADARA 0.4 `init` scaffold as a small, productized project skeleton.

`hadara init` should not produce a large required-reading burden. It should create the minimal project state, workflow reference, registry metadata, and task directory needed for agent-assisted development.

## Product Default Rule

The generated scaffold must be generic. It must not include HADARA-dev-specific validation commands, Docker workflows, npm release procedures, package names, local repository paths, or internal HADARA release history.

Projects add those details later as project-specific docs, registered design sources, or Task Capsule instructions.

## Normal Init Command

```bash
hadara init --json
hadara init --profile basic --json
hadara init --profile standard --json
hadara init --profile governed --json
```

No task-layout option exists in 0.4. The task schema is implied by the 0.4 protocol.

## `.hadara/scaffold.json`

```json
{
  "schemaVersion": "hadara.projectScaffold.v1",
  "hadaraProtocol": "0.4",
  "profile": "basic",
  "taskCapsuleSchema": "hadara.taskCapsule.v1",
  "docsRegistrySchema": "hadara.docsRegistry.v2",
  "managedSlotSchema": "hadara.managedSlot.v2",
  "createdWith": "hadara@0.4.0",
  "docsRegistryPath": ".hadara/docs-registry.json",
  "slotRegistryPath": ".hadara/slot-registry.json"
}
```

There is no `taskLayoutDefault` field. HADARA 0.4 has one task capsule schema.

## `docs/PROJECT_STATE.md`

`PROJECT_STATE.md` is current state, not history.

Recommended sections:

```text
Product
Current State
Active Work
Last 3 Completed Tasks
Current Known Problems
Next Recommended Step
Historical Index
```

Basic and standard profiles may include compact handoff-like continuation fields here. Governed projects may use a separate `AGENT_HANDOFF.md`.

`PROJECT_STATE.md` should not duplicate workflow command recipes, validation command lists, or per-task acceptance state. It should point to `docs/HADARA_WORKFLOW.md` for generic workflow behavior and to Task Capsules for task-local details.

## `docs/TASK_BOARD.md`

`TASK_BOARD.md` is an index.

Recommended columns:

```md
| ID | Title | Status | Capsule | Notes |
|---|---|---|---|---|
```

`Status` is an index projection of the canonical `TASK.md` TaskStatus. `Notes` is human/mixed free text and must not be part of the compact close-source hash.

## Files Not Generated by Default

These are generated only when the capability is enabled:

```text
docs/RELEASE_READINESS.md
docs/integrations/MCP.md
docs/integrations/HERMES.md
docs/integrations/DASHBOARD.md
docs/TEST_STRATEGY.md
docs/SECURITY_MODEL.md
```

`docs/TEST_STRATEGY.md` and `docs/SECURITY_MODEL.md` may be included by a governed project template only when the project explicitly opts into those governance concerns. Their generated content must remain generic and must not mention HADARA-dev validation infrastructure.

## Init Doctor Checks

`hadara init doctor --json` should report:

| Code | Meaning |
|---|---|
| `INIT_PROTOCOL_MISSING` | `.hadara/scaffold.json` is missing. |
| `INIT_PROTOCOL_UNSUPPORTED` | Scaffold protocol is not `0.4`. |
| `INIT_WORKFLOW_DOC_MISSING` | `docs/HADARA_WORKFLOW.md` is missing. |
| `INIT_AGENTS_COMMAND_COOKBOOK` | `AGENTS.md` appears to duplicate lifecycle/context command recipes. |
| `INIT_DOCS_REGISTRY_MISSING` | `.hadara/docs-registry.json` is missing. |
| `INIT_SLOT_REGISTRY_MISSING` | `.hadara/slot-registry.json` is missing. |
| `INIT_REQUIRED_READING_TOO_BROAD` | Registry default read path includes historical/spec drift documents. |
